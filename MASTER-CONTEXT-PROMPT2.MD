## 1. Краткое описание и текущий статус

**«Дорога домой»** — оригинальная семейная браузерная игра в жанре однотапового аркадного полёта. Воздушное путешествие состоит из шести коротких остановок. Игрок выбирает одного из пяти пилотов, взмахивает по нажатию/касанию, проходит ворота, собирает лапки, получает звёзды и открывает следующий маршрут.

### Что реально находится в репозитории после продолжения работ

- Одностраничный адаптивный сайт; Canvas-игра без runtime-сетевых запросов.
- 6 маршрутов, 5 базовых и 6 открываемых миссиями бонусных карточек, 8 миссий, 3 косметических наряда, три усиления, лапки, звёзды и локальный прогресс.
- Шесть открываемых заметок, финальное письмо, опциональное поздравление по дате в `assets/js/config.js` (значение по умолчанию `null`).
- Бесконечный режим, Web Audio, шесть тематических оформлений и сохранение в `localStorage`.
- 15 оптимизированных WebP; Pages-сборка включает только allowlist нужных сайту файлов и 8 используемых фото — ZIP/видео исключены.
- 9 Node-тестов, проверка сайта, 3 000 seed-попыток приближённого бота и Puppeteer E2E, добавленный в CI.

### Что ещё НЕ завершено и не должно описываться как готовое

Тематические объекты (падающие яблоки/капли/шарики) пока декоративны, а не отдельные игровые столкновения. Бот — приближённая модель и не доказывает доступность игры для людей. Нет ручного теста на реальном телефоне. GitHub Pages deployment блокируется настройкой репозитория: GitHub Pages API отвечает 404, а `deploy-pages` завершился с сообщением `Ensure GitHub Pages has been enabled`. Страница не считается опубликованной, пока владелец не включит Pages и deployment не завершится успешно.

### 2.4 Существенные противоречия старого контекста, исправленные здесь

1. Текст говорит одновременно о трёх питомцах (кот, собака, кот), пяти карточках (два человека и три животных), фотографиях питомцев и «обрезанных фото-карточках» людей. Нет подтверждённых портретов людей; не подменять их фотографиями животных.
2. Возраст/имена, некоторые питомцы и соответствия фото были заявлены как «рабочая интерпретация», но позже сформулированы как факт. Считать их настройками-кандидатами, пока владелец не подтвердит.
3. Старая таблица уровней и описание опасностей расходятся: ветер/капли/яблоки/шарики назначены неодинаково в разных разделах; разные варианты названия валюты/способностей и опечатки. Поддерживать один источник данных и словарь терминов.
4. «Без внешних ресурсов» не согласуется с предлагаемыми веб-шрифтами из CDN. В этой версии системные шрифты; никаких внешних runtime-запросов.
5. Требование «копировать дословно» чужую архитектуру/механику/содержание плохо совместимо с оригинальностью и отсутствием проверенной лицензии. Переносить только высокоуровневые идеи и независимо проектировать реализацию.
6. Старый документ предлагает тесты, CI, E2E и полный магазин как обязательный минимум, а одновременно задаёт дорожную карту на несколько pull request и использует «всё готово» как один проход. Это разные критерии завершения. Ниже явно отделены MVP и следующие этапы.
7. Уровни были рассчитаны для мира 720 px высотой и физических чисел, которые не соответствуют текущему Canvas 960×540. Не смешивать константы исходной игры с текущей физикой.

### 2.5 Ключевые риски и способы их снижать

- **Публичность семейных фото/истории Git — высокий риск.** Не добавлять исходное видео и ZIP в Pages artifact; уточнить у владельца разрешённые фото и подписи. Уже попавшие в публичную историю файлы не считаются приватными.
- **Pages не была активна на момент аудита.** Включить в Settings → Pages источник GitHub Actions; дождаться deployment environment, проверить Actions и URL. Не пушить в `main` из этой рабочей сессии.
- **Большой первоначальный scope.** Сначала надёжный MVP полёта/управления/сохранения; затем контент и магазин, только затем e2e и баланс.
- **Случайная сложность/сенсорное управление.** Текущие тесты проверяют данные/функции, не доказывают победу игрока. Добавлять детерминированный симуляционный бот и реальный браузерный сценарий.
- **Ошибки `localStorage`, resize Canvas, фоновой вкладки, повторных нажатий.** Сохранять безопасно; паузить при `visibilitychange`; ручная проверка iOS Safari/Android Chrome обязательна.
- **Скрытые публичные архивы в корне проекта.** Деплой строится через `tools/build-site.mjs` (allowlist), только перечисленные файлы идут в `dist/`. Не заменять его `cp -r . dist`.

## 3. Концепция и правила контента

**Название:** «Дорога домой».  
**Жанр:** семейный однотаповый аркадный полёт с воротами и короткими уровнями.  
**Тон:** солнечный, заботливый, с мягким юмором. Не изображать травму/жестокость; столкновение — комичное отряхивание/мягкое приземление.  
**Аудитория:** семья с детьми; конкретные возрастные обозначения и личные шутки добавлять только после согласования.

### Эмоциональная дуга

1. **У озера:** первый короткий и ясный полёт, знакомство с управлением.
2. **Парк качелей:** лёгкое движение ворот и порывы ветра.
3. **Бабушкин огород:** падающие яблоки/капли как визуальные и/или игровые опасности.
4. **Речной мост:** вода, рыбки/дополнительные сборы.
5. **Старый лес:** сумерки, светлячки, заметно более сложный маршрут.
6. **Дорога домой:** крыши/чердак, финальный мягкий финиш, благодарность и письмо.

Шесть уникальных тем не должны быть только сменой цвета фона. У каждой нужен хотя бы один узнаваемый объект/палитра, опасность или визуальный мотив, отдельная заметка и собственный post-level результат. Не использовать пугающие или опасные в реальной жизни советы.

### Персонажи

Имена из первого контекста — рабочие: **Поршик, Арчи, Грэйс, Егор, Лиза**. Не делать пользовательский ввод обязательным для старта. Настройки карточек находятся в одном модуле; если владелец изменит имена/состав, текст и доступность обновляются из того же источника. Портрет собаки/кота не должен выдаваться за фотографию ребёнка. Фото-аватары заменяемы на цветные иллюстрированные заглушки.

| Карточка | Пилотская особенность в текущем MVP | Балансный замысел |
|---|---|---|
| Поршик | 6 жизней | Прощающая карточка для первой игры |
| Арчи | 5 жизней, 30 лапок за ворота | Больше валюты, базовая гравитация |
| Грэйс | 6 жизней, немного мягче скорость | Предсказуемый плавный полёт |
| Егор | 4 жизни, чуть более сильный взмах | Реактивный быстрый пилот |
| Лиза | 4 жизни, меньшая гравитация | Дольше планирует, нуждается в контроле |

Портреты можно назначить только после подтверждения, что на фото именно указанный питомец. Условные строки с возрастом не выводить как факт.

## 4. Функциональные требования и правила игры

### Управление

- Касание/клик по игровому полю, пробел, ↑ или W — один взмах.
- Escape или кнопка паузы — пауза/продолжение.
- Не прокручивать страницу при касании игрового Canvas; при повороте/resize корректно менять canvas backing store и масштаб отрисовки.
- При сворачивании вкладки ставить игру на паузу.
- Обеспечить заметное управление клавиатурой, корректные focus-стили, reduced-motion и ясную кнопку включения/выключения звука.

### Полёт и финиш

- Игрок непрерывно продвигается по сцене. Взмах импульсный, гравитация ограничена максимальной скоростью падения.
- Ворота имеют достаточно широкое достижимое отверстие; последующие ворота не должны телепортировать безопасную траекторию за пределы возможного подъёма/спуска.
- При столкновении теряется жизнь; есть временная неуязвимость после удара, чтобы один объект не списывал несколько жизней подряд.
- Неуязвимость/щит не должны начислять звезду «без потерь», если сердечко реально списано.
- Три усиления: **Пузырёк заботы** (блокирует один удар), **Ловушка лапок** (временно увеличивает сбор), **Витаминная сладость** (неуязвимость). Длительности и визуальные эффекты — в общем конфиге, не разбросаны по рендеру.
- Финал раунда — понятная линия финиша, звёзды и кнопки следующего уровня/повтора.

### Баланс текущего MVP

Мир Canvas: **960×540 логических пикселей** с адаптивным CSS масштабированием. Входные параметры сведены в `assets/js/rules.js`.

| Уровень | Название | Ворот | Скорость (мир/сек) | Просвет |
|---|---|---:|---:|---:|
| 1 | У озера | 8 | 180 | 250 |
| 2 | Парк качелей | 9 | 185 | 245 |
| 3 | Бабушкин огород | 10 | 190 | 238 |
| 4 | Речной мост | 11 | 198 | 230 |
| 5 | Старый лес | 12 | 205 | 225 |
| 6 | Дорога домой | 13 | 210 | 220 |

Это параметры текущей версии, **не подтверждённый человеческий баланс**. `npm test` запускает приближённого бота для всех пяти базовых пилотов, 100 seed на маршрут; порог 60% — аварийный, а не целевой UX. Оценка не моделирует настоящую точность касаний/ошибки ребёнка и не заменяет пользовательский тест.

Звёзды: 1 — завершить уровень; 2 — собрать не менее 65% доступных отметок; 3 — завершить без потери жизней. Звёзды каждого уровня не уменьшаются при повторном худшем результате.

### Бесконечный режим

Открывается после первого законченного сюжетного уровня. Одна жизнь; записывается лучший результат по пройденным воротам. Текущая модель difficulty растит скорость и уменьшает отверстие/интервал до заданного предела. Добавить генератор уровня, который гарантирует достижимую геометрию и не оставляет бесконечную очередь за экраном.

### Лапки, сохранение и сброс

- Лапки начисляются за пройденные ворота, бонусы и финиш; Арчи получает дополнительную награду.
- Единая версия ключа: `doroga-domoy.save.v2`.
- Сохранение: разблокированные уровни, лучшая оценка звёзд, кошелёк, общий сбор, выбранный пилот, бесконечный рекорд, настройки звука, открытые заметки и миссии.
- Валидировать каждое поле сохранения и восстанавливаться после битого JSON, устаревшей схемы и отключённого хранилища. Запись после каждого финиша/значимого получения, а не обязательно на каждом кадре.
- Не сохранять персональную информацию, фото, имя ребёнка или дату рождения без явного решения владельца.

- Сохранять русский интерфейс и понятные подписи. Для интерфейсного текста не опираться только на emoji — поддерживать видимый текст и доступные labels.

### Публикация без утечки вложений

GitHub Pages workflow вызывает `node tools/build-site.mjs`, который копирует в `dist/` только `index.html`, `404.html`, CSS/JS и оптимизированные изображения игры, плюс `.nojekyll`. Не изменять workflow на загрузку корневого каталога. ZIP/MP4 никогда не копировать в Pages artifact.

Публикация предполагает Settings → Pages → Source = **GitHub Actions**, права workflow `pages: write` и `id-token: write`, успешные проверки и deploy. После пуша проверить Actions, Environment `github-pages`, `/game/`, фотографии и 404. При Pages `404` проверить настройки, а не сообщать, что игра уже опубликована.

## 7. QA и проверки

### Уже автоматизировано

`npm test` запускает Node unit-тесты, проверку файлов/разделов и 3 000 коротких seed-симуляций комбинаций «уровень × пилот». `npm run test:e2e` использует Puppeteer Core и установленный Chrome/Chromium. CI ставит Puppeteer и запускает браузерные проверки. `node tools/build-site.mjs` создаёт статический allowlist artifact.

### Обязательный следующий QA-шаг

1. Убедиться, что последний Puppeteer E2E на GitHub Actions проходит на настоящем Chrome.
2. Расширить сценарий: столкновение/жизнь, подбираемые усиления, прохождение главы, разблокировка следующего уровня, бесконечный режим и persistence миссий.
3. Проверить widths **320, 380, 768, 1280 px**, отсутствие переполнения/прокрутки во время игры, hover и клавиатуру.
4. Проверить робастность save при JSON `'{'`, `null`, неподходящем типе, выключенном `localStorage` и будущей схеме.
5. Проверить все 6 тем/опасностей, достижимую геометрию ворот, уменьшение сложности по настройке accessibility (если добавлена) и каждый персонажный модификатор.
6. Ручной чек на iOS Safari и Android Chrome: первый жест включает audio context, нет нежелательного zoom/scroll, ориентация и фон вкладки, касания не «дублируются».
7. Прогнать опубликованный Pages URL: относительные пути работают в подпапке `/game/`; нет внешних обязательных ресурсов; архивы/MP4 недоступны с сайта.

### Инструменты разработки

```sh
npm start
npm test
node tools/build-site.mjs
```

В dev-сервере слушать `0.0.0.0`; не использовать localhost из клиентского кода для обращения к сервису. Для этого проекта браузерный runtime вообще не обращается к API.
